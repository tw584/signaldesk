# SignalDesk Working Instructions

## Long-term objective

Build and publish SignalDesk as a trustworthy open-source product, then work persistently toward earning 10,000+ genuine GitHub stars through product usefulness, evidence quality, excellent documentation, reliable engineering, and ethical community growth.

The 10,000-star target is an ambition and measurement goal, not a guaranteed outcome. Never purchase stars, automate fake engagement, spam communities, or misrepresent traction.

## Product gates

- Prioritize problems repeated independently by many real people.
- Preserve original evidence, source links, dates, and epistemic status.
- Treat easy achievement as a hard gate: a qualified MVP should fit one developer and no more than ten working days, with limited integrations and no unresolved regulatory or platform dependency.
- Keep Ideas and Complaints as separate 20-item early-signal sections after refresh.
- Never fabricate demand, evidence counts, feasibility, competitors, users, or performance.

## Continuous execution loop

Unless the user pauses or changes the objective, keep moving through: collect evidence, improve ranking quality, validate feasibility, strengthen the product, test, document, prepare releases, publish approved changes, gather genuine feedback, measure adoption, and iterate.

Persistence does not expand authority. Stop for credentials, public/private visibility decisions, paid services, destructive actions, legal/privacy uncertainty, or external communications that the user has not approved.

## Existing-file review rule

When suggesting changes to existing prose, preserve the original wording and present proposed replacements as reviewable comments with both versions highlighted in purple when the format supports it. For code or formats without comments/highlighting, preserve the original content and clearly present the proposal before replacement.
